## 1. 产品概述

面向食用菌工厂化全产业链，把「菌包制备 → 灭菌 → 接种 → 培养 → 出菇 → 采收 → 冷链」七道工序，以及贯穿全程的环境、设备、质量、追溯数据统一到后台与四类应用中。

| 端 | 承载角色 | 核心能力 |
| --- | --- | --- |
| PC 管理后台 | 企业负责人、生产主管、质检员、追溯专员 | 六组一级菜单 + 32 页；工序台账、设备管控、预警闭环、追溯赋码与链上存证 |
| 移动应用端 | 车间操作工、设备运维、质检、仓储 | 4 主 Tab + 9 个现场作业入口；扫码开工、工序填报、过磅、抽检、预警处置、设备报修、冷库出入库 |
| 生产数据大屏 | 值班室、参观接待 | 单文件 6 视图：运营总览 / 环境设备 / 视频监控 / 生产管理 / 能耗管理 / 质量追溯 |
| 消费者溯源 H5 | 消费者、监管抽查 | 免登录扫码查批次履历、出厂检测报告、链上存证验证、扫码风控 |

**本期范围**：生产台账、环境与设备管理、预警闭环、追溯赋码与链上存证、移动端现场作业、数据大屏可视化、消费者溯源、权限与运维。**形态约束**：纯前端 HTML 原型，无后端、无构建步骤，数据用 `localStorage` / `sessionStorage` 模拟；全站离线可用，**禁止引入 CDN 资源**；PC 与移动端数据尚未打通。**页面总量 53 个**：PC 32 · 移动端 15 · 大屏 1（6 视图）· H5 2 · 门户与引导 3。

## 2. 端侧构成与导航

```
index.html（引导页）→ html/portal.html（统一门户，免登录）
                            │
      ┌─────────────┬───────┴───────┬────────────────┐
      ▼             ▼               ▼                ▼
 PC 管理后台      移动应用端      生产数据大屏      消费者溯源 H5
 applefarm_       applefarm_      applefarm_       applefarm_h5/
 backhand/        mobile/         dataanlye/       trace_h5.html
```

目录约定：`html/applefarm_backhand/` PC 后台 32 页（`js/shared/fungi-store.js` 为统一主数据源，含 `traceStats()` 追溯统计单点定义）；`html/applefarm_mobile/` 移动端 15 页（`css/mobile-design-system.css` 为设计系统）；`html/applefarm_dataanlye/` 大屏唯一入口 `da_index.html`（6 视图同文件切换，素材 `assets/campus_night.jpg` + `assets/cams/01~09.jpg`）；`html/applefarm_h5/` 消费者溯源 2 页（`js/trace-stages.js` 为 C 端环节口径）；`html/common/` 门户二维码、品牌图片与通用脚本。

**PC 后台**：深色侧边栏 + 顶栏 + iframe 内容区，未登录跳 `login.html`；一级菜单为系统首页 / 企业管理 / 生产管理 / 设备管理 / 预警管理 / 追溯管理 / 系统管理；顶栏含侧栏折叠、面包屑、站内搜索、预警通知面板、用户菜单、日期。**移动端**：底部 4 主 Tab —— 首页 `mb_home` · 监测 `mb_device` · 监控 `vr_panorama` · 我的 `mb_mine`；子页面统一 `mb-back-bar` 返回，不加底部 Tab。**大屏**：单文件 6 视图顶栏 Tab 切换，支持 `?view=overview|env|video|production|energy|trace` 直达。**H5**：以 `?code=` 或 `?c=`（8 位短码）带参免登录进入。**门户**：只做入口聚合与系统服务状态展示，认证在各端完成。

> 后台文件名沿用早期命名，与业务名不一致：`harvest_report`=高压灭菌、`harvest_record`=菌丝培养、`harvest_plan`=出菇培育、`harvest_process`=采收分拣、`harvest_storage`=仓储冷链、`material_io`=菌包制备、`farming_record`=无菌接种、`trace_query`=产品召回、`data_source`=监管对接。

## 3. PC 管理后台

### 3.1 系统首页 `home.html`

工作台含欢迎条（问候、日期与数据更新时间、天气、当前生产阶段）、6 张指标卡（在产批次 / 环境达标率 / 待处置预警 / 今日采收量 / 追溯码数 / 在产菇房数）、8 路菇房实景监控、生产智能快讯（7 条模型预测卡，点击跳对应工序页）、实时预警、待办任务、系统通知。指标卡每 5 秒刷新，取数来自 `FungiStore.stats()`、`FungiAlertData`、`FungiStore.traceStats()`。

### 3.2 企业管理

- **企业信息 `enterprise_info`**：基本信息 10 项 + 资质证书表（新建/编辑/删除/导出 CSV/批量删除）；证书状态按到期日自动推导（有效 / 即将到期 ≤30 天 / 已过期）。
- **厂区档案 `enterprise_base`**：五级空间模型 厂区 → 车间 → 出菇房 → 层架 → 架位；建档后不可删除只能停用，含在产节点或含在产下级的节点禁止停用；停用后版本号自增并写入变更历史（保留近 300 条）。
- **物料种质 `material_info`**：三 Tab 菌株种质 / 主物料 / 供应商；统计低库存物料数、待检数、资质待复核供应商数；抽屉展示关联批次与变动记录。
- **人员班组 `team_manage`**：四 Tab 班组 / 岗位 / 人员 / 派工；**关键约束**——关键工序人员证书过期或无效不得派工，状态记「已阻断」并写明原因，人员状态记「禁派」。
- **工艺标准 `guide_standard`**：五 Tab 工艺 SOP / 配方模板 / 接种等级 / 生长曲线 / 参数覆盖；内置 6 条 SOP；接种等级 A/B/C（A 级洁净度 100 级、污染率 ≤0.5%；C 级禁止放行须重新灭菌接种追责）；**参数三级覆盖就近生效**（批次 > 菇房 > 全局），模板存「下限 ~ 上限」且保存时校验下限 ≤ 上限。

### 3.3 生产管理（七道工序）

- **`material_io` 菌包制备**：每 50 袋抽 1 袋称重；上架数 > 装袋数红色阻断且不允许提交；出库/报废联动扣减物料库存，库存不足即阻断；配方状态 拌料/装袋/待灭菌/已灭菌。
- **`harvest_report` 高压灭菌**：温度曲线控制器自动采集，**不可手补、不可删改**，仅可追加说明，删除硬阻断；按 SOP-02 自动判定（保温段最低探头 ≥121℃ 自动通过，否则转人工复判，曲线缺口标「待复判」）。
- **`farming_record` 无菌接种**：**洁净度门禁**，未达 A/B 级禁止开工，C 级禁止放行并追责；判据沉降菌 ≤3.5 cfu；污染率 ≥3% 达预警线。
- **`harvest_record` 菌丝培养**：污染分档 ≥3% / 1%~3% / <1%；满袋率趋势含工厂均值参考线 92.6%；积温与培养天数双条件判定转潮。
- **`harvest_plan` 出菇培育**：进度枚举 催蕾 / 菇蕾分化 / 子实体生长 / 采收就绪。
- **`harvest_process` 采收分拣**：**预冷交接**，按 kg/1000 生成 YL-01 库存批次、保质期 3 天；已交接单不可重复交接，删采收单不回退已交接库存。
- **`harvest_storage` 仓储冷链**：库区 YL-01 预冷区 / LK-A / LK-B；**FIFO 优先出库**；保质期 ≤3 天临期批次标红。

### 3.4 设备管理

- **设备台账 `device_info`**：资产台账 + 状态分布 + 厂区点位图；回路号全厂唯一，作为电气寻址与备件关联依据；运行状态 6 态（运行/待机/离线/故障/联动/定时）。
- **环境数据 `env_monitor`**：越限事件 / 培养操作 / 杂菌污染 / 全区矩阵四类视图；5 项指标归一化（温度 0~30℃、湿度 50~100%、CO₂ 0~1500ppm、光照 0~400lx、负压 -30~0Pa）；每 30 秒刷新；杂菌 4 类（绿霉/青霉/曲霉/链孢霉），污染率阈值 AR-04 ≥3.0%。
- **设备控制 `device_control`**：远程下发设定值与启停；仅 `control=true` 可控，离线/故障态按钮禁用；每次下发写入指令流水；联动策略含触发条件、目标设备、延时、锁定方式、复位条件。
- **运维工单 `device_maintain`**：保养计划 + 工单闭环；类型 维修/保养/校准/巡检/更换/调试；**完成工单自动扣减备件库存并写出库流水**；保养到期自动生成待处理工单。
- **备品备件 `device_spare`**：台账 + 出入库流水 + 回路关联；库存状态 低库存/临界/充足；备件回路与设备回路一致时自动关联；更换到期日剩余 ≤15 天进入预警。

### 3.5 预警管理

- **预警管理 `alert_overview`**：统计卡（待处理 / 处理中 / 已闭环 / 超时已升级 / 今日新增，可切页签）；来源 4 类（环境越限、设备故障、污染超标、系统消息）；状态 3 态（待处理 → 处理中 → 已闭环）；**闭环五步** 派工 → 响应 → 措施 → 复核 → 关闭，处置措施必填；编号 `FA-日期-序号`。
- **预警设置 `alert_settings`**：预警规则 / 时效渠道矩阵 / 联动策略三表。**四色级别与时效**：红·紧急（SLA ≤1min，站内+短信+电话+App，超时升级厂长）· 橙·重要（≤3min，站内+短信+App，升级生产主管）· 黄·提醒（≤5min，站内+App，超时转重要）· 蓝·提示（≤30min，仅站内）。条件符支持 > ≥ < ≤ 超出区间 低于（等级）；**持续时长 (min)** 为 0 表示立即触发。内置 8 条规则 AR-01~AR-08、7 条联动策略 LK-01~LK-07，锁定方式分自动/手动复位/人工复核。

### 3.6 系统管理

- **系统设置 `system_settings`**：平台参数、安全策略（失败 5 次锁定 15 分钟、会话为浏览器会话级、记住密码 7 天、密码最小 6 位、admin 不可删禁用）、系统参数（离线判定周期、预警时效、备份周期与保留份数）、数据字典、操作日志、重置演示数据（保留账号/菜单权限/平台参数/监管配置）。
- **菜单设置 `menu_settings`**：角色菜单权限白名单（键格式 `角色:分组:菜单`）；勾选即该角色可见，保存后需以该角色重新登录生效；admin 恒可见全部菜单；支持菜单启停与排序。
- **用户设置 `user_settings`**：账号与角色权限矩阵；内置账号仅可停用不可删除；新增用户初始密码 ≥6 位。

**7 个数据字典**：`DIC-VAR` 品种 · `DIC-POLL` 杂菌类型 · `DIC-DEFORM` 畸形菇类型 · `DIC-NC` 不合格品类型 · `DIC-DISPOSAL` 处置方式 · `DIC-GRADE` 产品分级 · `DIC-TEMP` 冷链温区。字典增删即时同步各业务页下拉。

## 4. 追溯管理

### 4.1 全链条九节点口径

后台全链条录入与大屏追溯视图共用同一套节点定义（`trace_batch.html` 的 `NODES` 与 `da_index.html` 的 `TR_NODES` 逐字一致），顺序为：菌种 `strain`（必填菌种编号）→ 装袋 `bag`（配方编号）→ 灭菌 `sterilize`（灭菌锅号）→ 接种 `inoculate`（接种室）→ 培养 `culture`（培养架位）→ 出菇 `fruit`（出菇房）→ 采收 `harvest`（采收量 kg）→ 分级 `grade`（分级结果）→ 冷链 `cold`（库区）；各节点另有次要字段（用量、含水率、峰值温度与保温时长、沉降菌与接种量、培养天数与温度、潮次与 CO₂、一级菇 kg 与人数、一级占比、入库吨数与温度）。批次号 `MJ-YYMMDD-NN`，创建后进入 9 节点待录入态；完成度 = 已录入节点数 / 9，支持「已完成 9/9 / 录入中 / 未开始」筛选；录入时间 `YYYY-MM-DD HH:mm`，操作人必填；节点支持「补录」与「重新录入」（后者覆盖原值）。阶段下拉 6 项（菌包/灭菌/接种/培养/出菇/冷链），品种 4 项（平菇/杏鲍菇/金针菇/香菇）。

### 4.2 各追溯模块

- **追溯码管理 `trace_code`**：状态流转 未激活 → 已激活 → 已绑定 → 已打印；层级 批码/箱码/袋码；批量生成、批量打印（按批次分组）、激活、绑定、导出 CSV、批量删除。
- **区块链存证 `trace_blockchain`**：10 类上链节点、6 类存证内容类型；状态 待上链 → 上链中 → 已确认 / 上链失败；**重试策略**指数退避 `now + min(30, 2^retryCount)` 分钟，上限 3 次，超限须手动重试；哈希为 `0x` + hex，区块高度 >0。
- **产品召回 `trace_query`**：流程 发起 → 通知中 → 回收中 → 处置中 → 已完成；**三级召回时限** 一级（食品安全）24h / 二级（质量缺陷）48h / 三级（标签包装）72h；流向节点状态 已冻结/在途拦截/已通知/已召回/已拦截；**召回未闭环时解冻被阻断**；演练单不计入真实召回，目标平均回收率 ≥95%。
- **监管对接 `data_source`**：10 类报文上报 + 死信重发 + 每日对账；回执号 `湘监收〔2026〕MMDD-NN`，失败入死信队列，清零后自动闭环关联预警；报文携带企业编码签名。
- **溯源配置 `trace_config`**：两 Tab 溯源模板配置 / C 端溯源展示；展示模块 10 项，其中**检测报告强制启用不可关闭**；**检测报告管控（只读）**：每批次必须上传合格报告且有效期覆盖采收日期，过期/撤销/缺失一律禁止生成追溯码。C 端环节表 7 个固定 key 不支持增删，**「分级预冷」承载检测报告，为合规必需环节不可停用**；停用环节不出现在 H5 时间线，排序决定 C 端先后；数据源 `localStorage['h5_trace_stages']` 与 `applefarm_h5/js/trace-stages.js` 共用。
- **溯源统计 `trace_statistics`**：三 Tab 数据总览（8 张统计卡、近 7 日扫码趋势、扫码渠道占比、码状态分布、区块链指标与区块列表）/ 流向与覆盖（省份扫码 TOP12、认证证书覆盖、批次流向）/ 风控与监管（异常扫码、监管报送、开放 API Key、码段风控、召回管理）；取数经 `TraceStatStore.overview()`，auto 模式优先由 `FungiStore.traceStats()` 桥接。

## 5. 移动应用端

### 5.1 登录与主 Tab

- **登录 `mb_login`**：密码 / 微信登录（授权弹窗，未注册手机号拒绝）；内置账号 `demo / demo123`（访客）、`zhangjianguo / 123456`（车间操作工）、`admin / admin123`（管理员）；登录写入 `sessionStorage.isLoggedIn/loginUser/loginRole` 与 `localStorage.smartorchard_current_user`；密码错误累计 5 次锁定 30 秒。
- **首页 `mb_home`**：问候区（姓名取登录会话、岗位工号、当前菇房与生长阶段）、离线同步条、今日待办 2 项（抽屉内可关闭/采纳/执行）、当前菇房环境紧凑条（适宜度评分 + 四指标 + 阈值来源，可展开）、**GF-01 有未处置预警时置顶红色异常横幅「去处置」，处置后恢复适宜态**、常用服务九宫格、今日动态三联卡。环境卡与预警台账互通，读 `mushroom_alert_records` 中未完成且属于 GF-01 的记录，按红>橙>黄>蓝排序，评分 `max(40, 92 - 越限数×12)`。
- **监测 `mb_device`**：菇房选择器（GF-01/02/03、B2）；对照基准「出菇期配方 v3.2」评估适宜性；四指标读数与适宜区间；环境曲线（温度/湿度/CO₂ 三线 + 阶段色带 + 越限红点，粒度 1min/1h/1d）；越限提醒给建议处置；**6 台设备控制**（风冷热泵 1#/2#、超声波加湿器 5#、新风风机、循环风机 2#、LED 补光灯 3#），支持启停二次确认、阈值步进（温度 16~20℃/0.1、湿度 88~95%/1、CO₂ 400~800ppm/50、光照 100~200lux/10）、自动/手动切换、报修申请；**离线设备启停与阈值下发不可用**，阈值仅本地暂存、恢复在线后下发。

### 7.1 C 端七环节口径

`applefarm_h5/js/trace-stages.js` 定义 7 个固定环节，key 不可增删，与后台「C 端溯源展示」共用 `localStorage['h5_trace_stages']`，顺序为：原料进厂 `material`（主辅料逐批验收，含水率与杂质抽检合格后入库）→ 菌包制备 `substrate`（按配方自动计量拌料，含水率与 pH 检测，装袋并称重抽检）→ 灭菌接种 `sterilize`（高压灭菌保温后冷却，于 A 级无菌接种室接种）→ 发菌培养 `incubate`（培养房避光培养，满袋率与污染率随批次呈现）→ 出菇采收 `fruiting`（出菇房温湿度与 CO₂ 呈现，菇体成熟后人工采收）→ 分级预冷 `grading`（按菌盖直径与形态分级并强制预冷至中心温度）→ 冷链流通 `coldchain`（全程冷链配送，车厢温度定时采集，运输曲线可查）。环节详情页 `h5_trace_detail.html` 展示环节日期、作业地点、负责人、名称、描述与标签；环节被后台停用时改为「该环节已停止对外展示」提示。

**状态字段统一为字符串**：`submitted`（已提交）/ `pending`（离线待同步、工单待受理）/ `processing`（处置中）/ `repairing`（维修中）/ `done`（已完成、已处置、已闭环）。

### 9.3 主要存储键

`mushroom_fungi_store_v1` 后台统一主数据（`FungiStore`，含 `traceStats()` 追溯统计单点定义）· `mushroom_alerts_v1` / `mushroom_alert_matrix_v1` 预警数据与级别时效覆盖层 · `mushroom_op_log` 操作日志 · `mushroom_sys_settings` / `mushroom_sys_params` 平台与系统参数 · `snzg_user_accounts` / `snzg_permissions` / `snzg_menu_config` 后台账号、菜单权限与启停排序 · `snzg_space_history` 厂区空间变更历史 · `h5_trace_stages` C 端环节配置（后台与 H5 共用）· `smartorchard_trace_v1` 追溯批次/码/扫码/存证事件链（H5 与后台共用）· `smartorchard_sync_queue` 离线同步队列（跨端契约，勿改名）· `smartorchard_current_user` 当前登录用户 · `mb_staff_accounts` 移动端作业人员账号表 · `rememberedUser` / `rememberedPwd` 记住密码（混淆存储）· `mushroom_process_records` / `mushroom_scan_jobs` / `mushroom_harvest_records` / `mushroom_quality_records` 工序、开工、过磅、抽检台账 · `mushroom_alert_records` / `mushroom_repair_orders` / `mushroom_contamination_reports` / `mushroom_disease_history`（≤10 条）预警、工单、污染上报与识别历史 · `mushroom_cold_storage` / `mushroom_cold_logs` 冷库库存与流水 · `mushroom_msg_read` / `mushroom_sys_messages` / `mushroom_notify_prefs` 消息已读、公告、通知偏好 · `mushroom_reg_config` 监管对接配置 · `applefarm_trace_stats_mode` 溯源统计取数模式（auto/demo）· `portal_last_sys` 门户最近访问系统。
