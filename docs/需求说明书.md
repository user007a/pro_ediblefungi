## 第一章 产品概述

### 1.1 产品定位

食用菌工厂化农业数据管理平台面向**食用菌工厂化全产业链**，把「菌包制备 → 灭菌 → 接种 → 培养 → 出菇 → 采收 → 冷链」七道工序，以及贯穿全程的「环境 / 设备 / 能耗 / 质量 / 追溯」五类数据，统一到一个后台、四类应用中。

| 维度   | 定位                                                |
| ---- | ------------------------------------------------- |
| 企业   | 一体化生产管理后台，工序台账、设备管控、质量追溯全部在线               |
| 车间   | 移动端现场作业与环境设备操控，取代纸质台账和固定面板                        |
| 管理层  | 四个驾驶舱分角色决策，从经营、生产、设备、质量四个视角掌握全局              |
| 监管方  | 一物一码追溯 + 区块链存证 + 省级监管平台数据上报                   |
| 消费者  | 扫码即查的 H5 数字履历，免登录，看产地、看检测、看真伪                 |

### 1.2 建设背景

食用菌工厂化生产对数字化管理有三条刚性诉求：

- **环境刚性依赖**：子实体对温湿度、CO₂、光照、洁净度极其敏感，20 套出菇房控制器的参数必须集中管控、可远程下发、可回读校验；
- **批次强追溯**：七道工序链条长，任意环节数据缺失都会导致追溯断链；消费者与监管部门要求产品可核验到生产全过程；
- **能耗占比高**：制冷、加湿、通风、照明全年连续运行，必须分项计量到「每公斤菇耗多少度电」这一可比口径，才能识别高耗能环节并优化。

### 1.5 建设范围界定

**本期包含**：生产台账、环境与设备管理、追溯链路、移动端作业与操控、四个驾驶舱、消费者溯源、权限与运维。

**本期不包含**：认养管理、经营分析（独立模块）、销售与订单管理、商城管理、数据运营、模型管理配置、移动端运营后台。相关能力若在业务上必需，以**生产管理下的附属页面**或**驾驶舱内面板**形式实现，不单列模块。

### 2.4 大屏视图划分

大屏采用**单一入口 + 顶部导航切换**形式：门户点「数据大屏」直接落到「运营总览」，顶部 6 个 Tab 切换中央主视觉区，左右栏与底排共享。6 个视图各自解决一类决策问题：

| 视图         | 决策问题               | 中央主视觉区                       | 特色面板                                 |
| ---------- | ----------------- | ----------------------------- | ------------------------------------ |
| **运营总览**（落地页） | 经营层怎么看整体？          | 3D 厂区鸟瞰（8 个菇房建筑体，可点击进入）   | 菌房总览、环境监测、通风调控、CO₂ 浓度监测、设备运行、菌种分布、产量统计    |
| **环境设备**    | 某个菇房现在什么状态？设备怎么控？  | 3D 菇房内景（叠加实时环境浮标）                | CO₂ 与设备运行面板随所选菇房联动刷新             |
| **视频监控**    | 现场发生了什么？          | 3×3 视频宫格 + 回放时间轴 + 快照图集            | 实时告警列表、异常抓拍、通道占用率 / 存储收录 / 设备健康度 |
| **生产管理**    | 今天生产卡在哪道工序？        | 七道工序泳道 + 批次卡片                   | 工序达成率、待处理批次、任务督办                     |
| **能耗管理**    | 哪个车间最费电？          | 能耗热力 + 分项占比                    | 分项能耗构成 + 单位产量能耗排行 + 高耗能环节识别         |
| **质量追溯**    | 追溯链断在哪一环？          | 批次 → 环节 → 流向 可视化                 | 追溯覆盖率、链完整率、上链成功率、消费者查询量、召回预警   |

**共同交互**：

- **顶栏 Tab 常驻**：6 个视图，切换只替换中央主视觉区，不刷新整页；URL 带 `?view=` 可直接定位；
- **多级下钻**：KPI / 数值块点击 → 弹出「核心指标 + 详情数据 + 口径说明」三段式弹窗 → 表格行点击 → 跳后台详情页；
- **3D 交互**：拖拽旋转 / 滚轮缩放 / 右键平移；点击建筑体或设备点位跳转对应视图；
- **实时性**：KPI 与面板 30 秒 / 列表 60 秒 / 3D 场景浮标 5 秒；
- **1920×1080 一屏不滚动**，顶栏常驻显示在线设备数、天气、时钟、日期与全屏按钮。

| 角色         | 数据范围     | 核心权限                                       | 禁止事项         |
| ---------- | -------- | ------------------------------------------ | ------------ |
| 平台管理员 / 企业负责人 | 全厂      | 全部功能；驾驶舱；配方下发审批；召回审批；人员与权限管理     | 不可修改已上链追溯数据   |

| 追溯专员      | 全厂（追溯域） | 追溯码管理、追溯链补充、存证、召回、溯源统计、监管上报、投诉处理 | 不可改生产环境原始数据 |
| 监管查看（只读）   | 指定范围     | 驾驶舱、报表、追溯链、存证核验；数据脱敏；操作留痕            | 任何写操作均禁止    |

- 阶段曲线用「累计积温 + 培养天数」双条件判定，避免单一温度累计造成季节偏差。

#### 5.2.2 高压灭菌管理

| 字段组   | 字段                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------ |
| 基本信息  | 灭菌批次号、对应菌包批次、灭菌锅编号、装载量(袋)、装载方式、责任人、灭菌日期                                   |
| 灭菌曲线  | 曲线时序点（时间戳、锅内温度(℃)、压力(MPa)）、升压段、保温段（保温温度、保温时长(min)、最低点温度）、降压段、强制冷却段、曲线完整性标记（是否系统采集、采集点数、丢点率） |

**硬性规则**：

- 灭菌曲线必须由控制器或平台**自动采集归档**，不得手工补录曲线，人工只允许补充文字说明；
- 曲线是追溯链最强的客观证据，生成后**不可删除、不可修改**，只能追加异常说明；
- 锅内多点（默认 3 点）探头可配置，合格判定取**最低点**；
- 曲线出现缺口（断电等异常）时系统必须标记「曲线不完整」，该批次默认不通过自动判定，必须人工复判。

## 第六章 追溯管理（一级菜单）

> 承载于 PC 后台一级菜单「追溯管理」，共 5 个页面。以「一物一码 + 区块链存证」为核心，覆盖赋码、录入、存证、召回、监管上报全链路。

### 6.1 追溯码管理

**赋码规则**：

- 码结构 `<企业码>-<日期>-<流水号>`，例 `SNJG-20260101-0001`；支持**短码**（二维码短链后缀）与**明码**（数字串）双形态；
- 支持「一批一码」与「一盒一码」（箱/盒/袋级）两种粒度；
- **赋码前置校验（硬阻断）**：质检报告缺失或判定不合格的批次禁止赋码。

**档案字段**：品名、菌种、规格（如 2.5kg/箱、一级品）、等级、生产日期、保质期、生产主体（企业/合作社/基地）、产地、批号、关联追溯链 ID。

**标签打印**：模板化标签（品名、等级、规格、生产日期、保质期、追溯二维码、生产主体、追溯短链），支持批量打印与打印记录留存。

**扫码核验**：平台端扫码展示完整档案与验证结果；无码 / 伪造码 / 已召回码须明确提示。

**作废与补码**：作废需审批并留痕；补码必须关联原码并注明原因。

### 6.2 全链条追溯数据录入

**追溯链七环节**：

```
① 原料进厂 → ② 菌包制备 → ③ 灭菌接种 → ④ 发菌培养 → ⑤ 出菇采收 → ⑥ 分级预冷 → ⑦ 冷链流通
```

| 环节      | 自动同步来源              | 人工补充项               | 关键字段                      |
| ------- | --------------------- | --------------------- | ------------------------- |
| ① 原料进厂  | 物料台账、进货验收单            | 供应商、到货检测、含水率复测       | 原料名称、批次、产地、含水率、质检结论   |
| ② 菌包制备  | 拌料与装袋记录                 | 拌料机清洁记录、异常说明           | 配比、投料量、装袋量、袋号段      |
| ③ 灭菌接种  | 灭菌曲线、接种记录                | 接种区消毒记录、复判说明           | 灭菌曲线、保温温度时长、接种环境、菌种批次 |
| ④ 发菌培养  | 培养记录 + IoT 温度曲线          | 翻袋次数、杂菌处理                 | 满袋率、污染率、培养天数、累计积温   |
| ⑤ 出菇采收  | 出菇记录 + IoT 环境曲线           | 畸形菇处理、抽检记录               | 喷淋补光、菇蕾密度、采收重量与分级    |
| ⑥ 分级预冷  | 分拣称重、入库记录                | 感官抽检、不合格品处置凭证             | 分级重量、合格率、冷库温湿度、效期   |
| ⑦ 冷链流通  | 出库记录                     | 承运方信息、渠道流向                 | 出库时间、去向、冷链车号、温度区间    |

**规则**：

- 自动同步优先，环节数据默认从生产平台拉取，人工只补充系统无法采集的关键项；
- 人工补充项标注录入人与时间，与自动数据一同上链；
- 环节可配置启用/停用，对监管上报时按规范输出完整链路；
- 追溯链生成后**不可删除**，只能追加修订并留痕。

### 6.3 区块链存证管理

| 要求   | 规格                                                                                   |
| ---- | ------------------------------------------------------------------------------------ |
| 上链内容  | ① 生产环境：菇房温湿度/CO₂/光照在关键节点的**聚合摘要**（批次期间均值、极值、越限次数与哈希明细）；② 质检报告：文件哈希 + 判定结论 + 签发机构 + 有效期；③ 投料数据：原料批次号与配比的哈希；④ 流通数据：出库时间、去向、承运方的哈希；⑤ 关键节点时间戳 |
| 上链时机  | 环节完成即上链；批量导入与高频量测做**聚合后上链**，避免链上数据爆炸                                  |
| 存证结构  | 区块高度、上链时间、交易哈希、数据指纹（SHA-256）、存证状态（待上链/上链中/已确认/上链失败）                   |
| 链上验证  | 输入存证包 → 校验数据指纹与链上哈希一致性 → 输出 `✓ 链上验证通过` / `✕ 验证失败：<原因>`       |
| 防篡改   | 链上数据只增不改；平台侧任何修改都会导致指纹不匹配并被验证环节检出                                  |
| 消费者核验 | H5 端展示「区块链存证」区块，用户可自行点击「链上验证」                                      |
| 失败处理  | 上链失败进重试队列（指数退避），连续失败告警；本地保留完整副本，不因链上失败而丢失                        |

## 第十二章 权限与数据字典

### 12.1 权限模型

```
用户 (sys_user)
  └─ 角色 (sys_role)  ── 多对多
       └─ 权限点 (sys_permission)  ── 树形，与第 2.3 节菜单树逐项同步
            ├─ 菜单权限：控制侧边栏项可见性
            ├─ 操作权限：view / add / edit / del / export / approve / control
            └─ 数据权限：本人 / 本班组 / 本车间 / 全厂 / 指定范围
```

**数据级权限要点**：

| 场景            | 判定逻辑                                                     |
| ------------- | -------------------------------------------------------- |
| 操作工查看环境数据   | 仅本人负责的菇房（由排班/派工确定），列表默认只显示负责房                    |
| 操作工操作设备      | 仅「允许操作模式」含「远程」且未被锁定停用的设备；加热/加湿回路需当班主管授权       |
| 质检员查看批次      | 全厂批次可见，但只能编辑质检相关字段，生产字段只读                           |
| 追溯专员编辑追溯链    | 可补充人工项；自动同步项只读；已上链内容需追加修订记录                        |
| 监管查看（只读）      | 只能访问指定车间与时间范围；手机号、身份证脱敏；导出需水印与审批                 |

**审计**：所有写操作记录操作日志（用户、模块、动作、对象、变更前后值、IP、时间、结果）；控制类操作额外记录「下发人 / 指令内容 / 执行回读值」；日志不可删除，保留 ≥180 天。

### 12.3 核心指标口径

## 第十三章 接口与数据规范

### 13.1 接口通用约定

| 项     | 约定                                                                    |
| ----- | --------------------------------------------------------------------- |
| 协议   | HTTPS + RESTful + JSON；驾驶舱实时推送用 WebSocket；设备上行用 MQTT 3.1.1 over TLS |
| 路径   | `/api/{模块}/{资源}`，例 `/api/iot/env-curve`、`/api/production/batch/{id}` |
| 版本   | 路径版本 `/api/v1/...`；不兼容变更走新版本并保留旧版 ≥6 个月                         |
| 鉴权   | 应用密钥 + HMAC-SHA256 签名 + 时间戳 + 随机数防重放；用户态用 JWT（Access 2h / Refresh 7d） |
| 幂等   | 所有 POST 携带 `X-Request-Id`，服务端 24 小时内去重                              |
| 分页   | `page` / `size`（默认 20，上限 200）；响应含 `total` / `page` / `size` / `items`  |
| 时间   | ISO 8601，统一 `Asia/Shanghai`；设备原始时间戳单独存 `deviceTime`                    |
| 错误   | 统一 `{code, message, requestId, details}`                                      |
| 限流   | 按调用方配额；写接口默认 60 次/分钟，超限返回 429 与 `Retry-After`                |
